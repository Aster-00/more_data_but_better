# Progress log

The story of the experiments: what each run did, what changed from the previous run, and what it showed. **No score tables here.** All numbers come from generated tables in `docs/tables/` (do not edit those by hand):

| Table | What | Generated by |
|---|---|---|
| `split_summary.md` / `.csv` | R runs: validation, dev and test scores per model, per-dialect dev F1, leaderboard submissions (T) | `python -m src.evaluation.summarize_runs` |
| `quality_summary.md` / `.csv` | Q: quality measurements of data sets | `python -m src.quality.summarize_quality` |
| `scorer_summary.md` / `.csv` | S: scorer validation against human gold | same |
| `generator_summary.md` / `.csv` | G: generator feasibility checks | same |

Data versions (D1–D4) are in `data.md`, decisions in `decisions.md`, the model roster in `CLAUDE.md`.

**IDs.** A run `R<NN>` is one fixed setup (prompt, data, training settings); each model tried under it is `R<NN>-<model>`, so models are compared only within a run. Seeds are folded into one row as mean ± std. `G<NN>` = generator checks, `Q<NN>` = quality measurements, `S<NN>` = scorer validation, `T<NN>` = leaderboard submissions. Register every new result folder in `configs/runs.json`, regenerate the tables, then add the run's notes here.

**Evaluation.** Model selection uses the MLADI dev set (120 sentences, 8 dialects) with the leaderboard's settings (max length 128, threshold 0.3); main metric macro F1. Seed spread is about ±1 point and the dev set is small, so differences under ~2 points are noise.

### T01 / T02: first leaderboard submissions (2026-10-08)
- **Setup:** best dev seed of R03-marbertv2 (T01, seed 44) and R03-arabertv02_twitter (T02, seed 43), `predict_binary_outcomes`. Scores, repos and commits: `split_summary.md` → Leaderboard submissions.
- **Result:** MARBERTv2 67.71, AraBERTv02-Twitter 67.31 test macro F1 (ranks 3 and 4 when read). 0.4 apart with one submission each: the test set does not rank the two.
- F1 falls about 10 points from validation to dev and 3 more to test. The validation split shares the training data's automatic labels, so it overstates performance on human labels; use it for epoch selection only.
- **Recall** falls most from validation to dev (90–91 → 72–75) and is similar on test: the models reproduce the automatic labels' multi-dialect pattern but miss human-valid dialects. **Precision** holds on dev (≈70–73) and drops only on test (62–64). Possible reasons, untested: the three test-only dialects (Iraq, Morocco, Saudi_Arabia) and a different mix of single- and multi-dialect sentences. The leaderboard gives only macro scores, so this cannot be checked per dialect.
- On test both models mark too many dialects per sentence. The threshold is fixed at 0.3, so a stricter cutoff would have to be built into the model (training, or lowering the output bias), chosen on dev, not test.
- The splits differ in dialects, label source and size, so rows are not strictly comparable. Macro F1 is averaged per dialect, so it is not the harmonic mean of macro P and R.

- **Setup:** `scripts/check_generators.py`, 4 sentences each for Egypt, Morocco, Syria, Saudi_Arabia, Iraq; one English instruction naming the dialect; temperature 0.9, top-p 0.95, top-k 50, max 48 new tokens, seed 42.
- **All six generators fit the 8 GB card in 4-bit** with ≥ 1.8 GB to spare (Gemma and Qwen3 are the tightest). Longer outputs or bigger batches are untested. Speeds are comparable only at the same batch size.
- Reading of the outputs (Claude, 20 sentences each; translations and refusals counted by hand):
  - **Jais-2:** clearest dialect markers (Iraqi ماكو/شلونك, Egyptian النهاردة, Syrian كتير). All 4 Moroccan outputs came out in Arabic Presentation Forms and were cut off; NFKC would map them back, but only as an explicit, logged step. Low variety (يا سلام على هالخير والبركة 3×).

### Q01: quality reference on real data (2026-10-06)
- Reference values for comparing synthetic sets (measure them with the same `--sample 2000`).
- **The DID scorers agree with the LahjatBERT single label on only 62% (nadi) / 49% (madar) of real tweets** (kappa 0.55 / 0.38; with each other 0.26). A top-1 DID fidelity filter would therefore reject about 40% of real data: set fidelity thresholds relative to these numbers, not to 100%. Per dialect, DID-nadi agreement is 0% for Bahrain, Jordan and Palestine (small n) and 82% for Egypt.

### S01: scorer validation against human gold (2026-10-06)
- Checks the scorers against the human MLADI dev labels (label trust rule) before using them as fidelity filters. Commit `3f39088`.
- Low macro F1 is expected (single-label scorers vs multi-label gold, so recall is capped). What matters for a filter is **precision / top-1 in gold**.
- **DID-nadi is clearly the better filter:** top-1 in gold 81% vs 63%, macro precision 80–87 vs 53–59; agrees with Q01. Evidence for the open DID-variant question, not decided yet.
- **Half the dev sentences cannot be checked:** the top country is outside the 8 dev dialects for 61 (nadi) / 55 (madar) of 120 sentences.
- Per dialect (nadi): Egypt is reliable (P 96); Jordan (P 50) and Syria (P 56) are weak, so Levantine fidelity checks will be the least trustworthy.
- **ALDi:** more dialectal sentences are valid in fewer dialects (ρ = −0.44; mean ALDi 0.17 for sentences valid in all 8 vs 0.65–0.78 for 1–5), consistent with ALDi as a proxy for dialect specificity. E5 has no labelled target, so it is not validated.

### Q02: quality of the G01 outputs (2026-10-07)
- The 20 G01 sentences per generator after the pipeline's parser, scored with `src/quality/measure.py`, against a size-matched real D1 set with the same dialect counts (set-size-dependent measures need that). Commit `68d1e50`.
- **Very small samples:** with n = 20, one sentence moves top-1 agreement by 5 points; a 95% interval is about ±20. Only differences of ~25+ points mean anything.
- **Dialect fidelity (DID-nadi top-1):** real 60%; Fanar and Falcon-H1 55%, Jais-2 and ALLaM 50%, Gemma 40%, **Qwen3 15%**. Only Qwen3 is clearly below real data.
- **Dialectness (ALDi):** real 0.71; most generators 0.62–0.68, Fanar 0.53 (partly its same-line English translations), **ALLaM 0.23** (mostly MSA).
- **Every generator is less diverse than real tweets** (E5 distance 0.126–0.140 vs 0.172; Vendi 1.99–2.11 vs 2.48). The most consistent finding, but still 20 texts each.
- **Jais-2 repeats itself** (Self-BLEU 0.253 vs 0.028 real; one near duplicate within its set). **Gemma writes very short texts** (5.5 words vs 11.3 real). No other set has exact or near duplicates, and no generated text is a near duplicate of D1.
- Leftovers the parser does not remove are scored as text (Fanar's translations, ALLaM's refusals, Jais-2's presentation-form fragments), so scores after a parser fix could differ.
