# Sentiment progress log

Run notes for the sentiment track (ArSarcasm-v2). Same conventions as `../progress.md`: what each run did, what changed, what it showed; no hand-written score tables. Data versions are in `data.md`, decisions in the shared log `../decisions.md` (tag `[SA]`).

**IDs.** Sentiment runs are prefixed `SR<NN>` (training), `SG<NN>` (generation), `SQ<NN>` (quality), so they never clash with the dialect track's R/G/Q IDs.

**Evaluation.** Model selection on the S1 dev split (1,246 tweets). Main metric macro F1 over NEG/NEU/POS, with per-class F1. The official test set (3,000) is scored only for final results.

### SG01: open synthetic sets, zero-shot, 4 generators (started 2026-10-16)
- **Question:** which generator's open (unconstrained) synthetic tweets help a sentiment classifier, at a fixed size of 500 per variety × sentiment cell? Condition 2 of the design; choices in SD-004.
- **Setup:** `python -m src.sentiment.generate`, one set per generator: Jais-2-8B, Fanar-1-9B, Qwen3-8B, Aya-Expanse-8B (configs `configs/sentiment/generation/sg01_{jais2,fanar,qwen3,aya}.json`), 4-bit NF4, batch 8, T 1.0 / top-p 0.95 / top-k 50, max 96 new tokens, seed 42. Template `prompts/sentiment/open_v1.json` (variety + sentiment with a one-line class definition; zero-shot). 650 requests per cell (msa/egypt/gulf/levant × NEG/NEU/POS), filtered with `configs/filtering/sentiment.json`, then 500 per cell sampled (`src.sentiment.select_synthetic`, seed 42); if a cell is short, the queue tops the set up to 900, then 1,300 requests per cell. Outputs `data/synthetic/sentiment/sg0N_*.{jsonl,filtered.jsonl,rejected.jsonl,selected.jsonl}`, stats `results/filtering/`.
- **Post-processing (sentiment only):** `**` bold markers removed before parsing; a same-line English translation (≥ 3 Latin words after the Arabic) is cut (`translation_stripped`); links/mentions → `URL`/`USER` as in S1 (`text_raw` keeps the original).
- **Smoke tests (24 requests = 2 per cell, `--limit 24`):** Jais-2 2.59 texts/s (peak 6.0 GB), 2 of 24 unparsed (one bolded tweet, one English-only tweet), one exact repeat within the same cell. Clearly dialectal egypt/gulf/levant text, sentiment as requested. Its file was made before the `**` and URL/USER fixes; re-parsing its raw outputs with the fixed code recovers the bolded tweet. Fanar 1.26 texts/s (peak 5.5 GB; one tweet with Chinese characters mid-sentence, heavy diacritics in places), Qwen3 1.70 (6.1 GB; gulf/levant drift to Egyptian, several broken sentences, one repetition loop, as in G01), Aya 2.27 (5.7 GB; fluent, clear dialects, many emoji). Fanar's smoke file used the old parser too.
- **SG01 Jais-2 set collapses to a few tweets per prompt (watchdog, 2026-10-16 07:57; for Ammar).** Zero-shot with one fixed prompt per cell, Jais-2 at T 1.0 / top-p 0.95 repeats itself almost verbatim: after 10,800 requests (900 per cell) only 2,757 texts survive the filter (exact duplicates 7,347, near duplicates 658 more). Worst cells: msa/NEU 10 distinct texts in 1,133 (one sentence 826×), msa/NEG 51; best egypt/POS 635. Not a sampling bug (each batch has its own seed, sampling on; the 2 msa/NEU smoke-test outputs were already identical). Shortfalls after 900 per cell: msa 466 / 492 / 336 (NEG/NEU/POS) of 500, egypt 290 / 395 / 96, gulf 131 / 290 / 204, levant 144 / 297 / 102. The 1,300 top-up cannot fill msa, so the queue will skip SR02 training as designed and go on with Fanar. Prompts, sampling and filters were left unchanged overnight. **Decision needed:** train on the deduplicated set at its actual (unequal) size, keep duplicates, or change the open condition (e.g. higher temperature, several tweets per request); each changes what "open generation" means.

### SQ01: quality of the SG01 sets (2026-10-17)
- **Question:** how do the SG01 sets differ from real tweets in balance, dialect, diversity and label quality?
- **Setup:** `python -m src.sentiment.measure_quality` (SD-005), 2.5 min on the GPU, uncommitted code. Selected sets; 3,000-text samples (seed 42) for MTLD, topic spread and Vendi; real reference = S1 train (fidelity: S1 dev). ALDi MSA cutoff 0.175 (from S1 train). Output `results/quality/sentiment/sg01_quality.json`, table `tables/dataset_quality.md`.
- **Results:** see `tables/dataset_quality.md`.
  - **Every generator is far less diverse than real tweets:** topics covered 7–11 of 30 (real 29), Vendi 2.8–3.2 (real 4.0), MTLD 323–1,123 (real 2,518). Fanar is the most varied in wording (MTLD 1,123), Qwen3 and Aya cover the fewest topics.
  - **The synthetic labels are "too clean":** fidelity 89–98% vs 80% for real dev tweets with the same classifiers. NEG and POS are near 100% for every generator; NEU is the weakest (74–90%). Generated tweets express their sentiment in obvious, prototypical ways, which a real-trained classifier finds easy. Consistent with SR02: the synthetic POS tweets did not help real POS.
  - **Dialect is about as real:** MSA share in dialect cells 20–25% for Fanar/Qwen3/Aya (real 22%), dialectness 0.48–0.57 (real 0.54). Jais-2 is the most dialectal (0.69, 9.6% MSA), but its set is tiny and repetitive (77.7% repeats).
  - **Takeaway: open zero-shot generation gives balanced, dialect-realistic but narrow and prototypical data (few topics, low semantic diversity, unrealistically clear sentiment)** — a plausible reason why it added nothing in SR02, and the concrete gap for the controlled condition (topics, sarcasm, ambiguous/neutral cases).
