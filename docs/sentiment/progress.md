# Sentiment progress log

Run notes for the sentiment track (ArSarcasm-v2). Same conventions as `../progress.md`: what each run did, what changed, what it showed; no hand-written score tables. Data versions are in `data.md`, decisions in `decisions.md`.

**IDs.** Sentiment runs are prefixed `SR<NN>` (training), `SG<NN>` (generation), `SQ<NN>` (quality), so they never clash with the dialect track's R/G/Q IDs.

**Evaluation.** Model selection on the S1 dev split (1,246 tweets). Main metric macro F1 over NEG/NEU/POS, with per-class F1. The official test set (3,000) is scored only for final results.

### SR01: real only, all roster classifiers (started 2026-10-13 14:55)
- **Question:** how well does each classifier do on Arabic sentiment with real data only? This is the condition-1 baseline that the synthetic conditions will be compared against.
- **Setup:** S1 train (11,208) → epoch chosen on S1 dev (1,246) → official test (3,000) scored once. Code: `src/sentiment/train_classifier.py` (BERTs), `src/sentiment/train_lora_classifier.py` (LLMs, 4-bit QLoRA). Configs `configs/sentiment/sr01_*.json`. Queue `scripts/sentiment/queue_sr01.sh`, log `results/sentiment/queue_sr01.log`.
- **What carries over from the dialect track:** same hyperparameters as the dialect BERT recipe (D-008: dropout 0.3, 8 frozen layers, lr 5e-5, batch 24, max length 128) and the R08 LLM recipe (LoRA r 16, lr 1e-4, 2 epochs, same batch sizes per model).
- **What changed for sentiment:** 3-class softmax + cross-entropy instead of 18 sigmoids + BCE; prediction = argmax (no threshold); BERT warmup is 10% of steps (500 steps would be more than one epoch here) and up to 3 epochs (best by dev); no extra validation split, since S1 dev plays that role.
- **Seeds:** BERTs 42/43/44; LLMs 42; Jais-2 (best) and Aya (0.8 behind on dev) get seeds 43/44 (SD-003, queue `scripts/sentiment/queue_sr01_seeds.sh`, started 2026-10-14).
- **Code version:** all SR01 runs used the code committed in `8db19fe` (no change to `src/sentiment/`, `configs/sentiment/` or the queue since). The code was committed while the queue ran, so `git_commit` in the logs is `91b8857` (BERTs, Jais-2, Qwen3, smoke tests; finished before the commit, that commit does not contain `src/sentiment/`) or `8db19fe` (Fanar, Aya, Falcon-H1).
- **Results (queue finished 2026-10-14 01:40, all 8 models):** see `tables/sentiment_summary.md`.
  - **Jais-2 is best on dev and test** (one seed), about 2.4 points dev / 2.7 test above MARBERT, ~5× the BERT seed spread. It is better on every class. Its best epoch was the first one.
  - **MARBERT ≈ MARBERTv2 > AraBERTv02-Twitter** on dev (difference v1/v2 within seed spread).
  - **Qwen3 lands with the BERTs** despite being ~50× larger and ~40× slower: size alone is not what helps, Arabic-centred pretraining (Jais-2) likely is.
  - **Dev → test drop of ~13–14 points for every model, almost all in NEU.** Test NEU F1 is ~48–52 vs ~80–82 on dev; most gold-NEU test tweets are predicted NEG. Matches the label shift of the official split (NEU 46% of train, 25% of test). Synthetic data cannot fix this, so condition comparisons should be read on dev and on per-class test F1, not only test macro F1.
  - **Overnight LLMs:** Aya (80.27 dev) and Fanar (79.42) are second and third on dev, above the best BERT; Falcon-H1 (77.93) sits with Qwen3 and the BERTs. On test, Fanar (66.63) is ahead of Aya (65.56); with one seed each, that order is not settled.
  - **Ranking pattern:** the Arabic-centred or strongly multilingual LLMs (Jais-2, Aya, Fanar) beat the BERTs on dev; Qwen3 and Falcon-H1 do not. Single seeds, so this is a pattern to confirm, not a result.
  - **Cost:** one LLM seed took 79 (Qwen3) to 188 min (Falcon-H1); a BERT seed takes 2 min.
  - Falcon-H1's first-epoch training loss was very high (2.97 vs 0.72–0.78 for the others) before settling in epoch 2: an unstable start, possibly from the hybrid Mamba layers with this learning rate. Not tuned (same recipe for all LLMs).
  - Smoke tests: all five LLMs fit 8 GB (peak 6.6–7.9 GB).
  - Small known discrepancy: LLM dev scores after reloading the saved adapter differ by ~0.2 from the dev score at the chosen epoch (Qwen3 78.04 → 77.82, Fanar 79.24 → 79.42; Aya and Jais-2 unchanged), probably because peft keeps layer norms in fp32 during training while the reloaded model keeps them in bf16. Same in the dialect pipeline. The reported score is the reloaded one.
